# Body — Ears V0.1

**Status:** First executable audio-input slice.

## Purpose

Ears V0.1 proves the Body can receive sound from the user's microphone without installing a
local application runtime.

The browser remains only the hardware bridge:

```text
local microphone
      ↓
browser getUserMedia() + MediaRecorder
      ↓ HTTPS
BrowserAudioIngress
      ↓
transient AUDIO Percept
      ↓
BodyRuntime.hear()
      ↓
Mind interpretation later
```

## Runtime boundary

The Codespace owns:

- the Body runtime;
- validation of incoming audio;
- the transient audio percept;
- the sensory API contract.

The browser owns only:

- microphone permission;
- short audio capture;
- encoding the captured clip as a data URL;
- sending that clip over HTTPS.

No local Python process is required.

## Audio Percept

Ears V0.1 accepts browser-recorded audio formats commonly emitted by `MediaRecorder`, including
WebM/Opus, Ogg, WAV, MP4 audio, and MPEG audio.

Each accepted observation becomes:

```json
{
  "modality": "audio",
  "source": "browser-microphone",
  "summary": "Audio clip received from browser microphone.",
  "metadata": {
    "media_type": "audio/webm",
    "duration_ms": 1250,
    "transient": true,
    "transport": "browser"
  }
}
```

Limits for the proof slice:

- maximum duration: 30 seconds;
- maximum encoded audio payload: 8 MB.

The browser page automatically stops a test recording after 10 seconds.

## Evidence and memory boundary

The live microphone stream is transient sensory material.

`BrowserAudioIngress` keeps only the latest unconsumed clip. Once `BodyRuntime.hear()`
consumes the percept, the ingress clears it.

When the Mind deliberately admits that clip for interpretation, the exact audio bytes are
preserved as an immutable sensory evidence artifact before transcription. This is evidence
storage, not durable cognitive memory.

Ears themselves still:

- do not decide what the audio means;
- do not decide whether a semantic memory should be formed;
- do not change identity or belief state.

See [0010 — Sensory Evidence Artifacts V0.1](0010-sensory-evidence-v0.1.md).

## Browser proof

When the Codespace-hosted application is available, open:

```text
/body/ears
```

Then:

1. press **Start listening**;
2. allow browser microphone permission;
3. speak briefly;
4. press **Stop and send** or wait for the 10-second automatic stop.

The browser submits the captured clip to the remote Body. It then consumes that exact percept
through `BodyRuntime.hear()`.

## V0.1 success criterion

Ears V0.1 is proven when the page reports:

```text
BODY CAN HEAR
```

and offers playback of the transient clip that travelled through the Body.

## Deliberately not included yet

- speech-to-text;
- speaker identification;
- sound classification;
- wake words;
- continuous listening;
- autonomous microphone activation;
- continuous/background raw-audio storage;
- direct conversion of heard speech into memory.

Those belong after the basic sensory path is proven.
