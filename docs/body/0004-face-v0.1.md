# Body — Face V0.1

**Status:** First executable avatar slice.

## Purpose

Face V0.1 proves that an avatar expression is not merely local browser behavior. The expression
travels through the Body's existing `ExpressionIntent` contract before the browser applies it to
the VRM avatar.

```text
expression request
      ↓
ExpressionIntent(modality=avatar)
      ↓
BodyRuntime.present_intent()
      ↓
BrowserAvatarOutput
      ↓
browser poll
      ↓
VRMExpressionManager
      ↓
visible face
```

## Runtime

The browser renderer uses the locked avatar stack:

- Three.js 0.180.0
- @pixiv/three-vrm 3.5.5
- VRM 1.0 avatar assets

The versions are pinned in the Face V0.1 browser page so the proof slice is reproducible.

## Avatar loading

Face V0.1 does not depend on a third-party avatar.

[Avatar V0.1 — Genesis](0005-avatar-v0.1-genesis.md) now supplies the default owned VRM. The
browser loads Genesis automatically from the Body API. The file chooser remains available so any
replacement owned `.vrm` can be loaded directly inside the browser without changing the Mind or
Face contract.

## Expression boundary

The server-side `BrowserAvatarOutput` accepts only avatar `ExpressionIntent` objects.

For V0.1 the expression metadata is:

```json
{
  "expression": "happy",
  "weight": 1.0
}
```

Weight must remain between `0.0` and `1.0`.

The adapter holds only the latest unconsumed intent. Once the browser consumes it, the pending
intent is cleared. Expression commands are therefore transient Body output, not durable memory.

## Browser proof

When the Codespace-hosted application is available, open:

```text
/body/face
```

Then:

1. confirm Genesis loads automatically and the page reports `FACE ATTACHED`;
2. press **Neutral**;
3. press **Happy**;
4. optionally select another owned VRM to prove avatar replaceability.

Each button posts the expression through the Body API. The browser then consumes that
`ExpressionIntent` and applies it through the VRM expression manager.

## V0.1 success criterion

Face V0.1 is proven when:

- an owned VRM renders in the browser;
- Neutral passes through the Body expression boundary and is visibly neutral;
- Happy passes through the same boundary and visibly changes the avatar expression;
- changing the avatar file requires no change to Mind identity or memory.

## Deliberately not included yet

- final avatar appearance;
- avatar customization UI;
- lip synchronization;
- speech coupling;
- blinking automation;
- gaze tracking;
- gestures;
- body animation;
- VRM Animation clips;
- persistent expression state.

Those belong after the basic Face output path is proven.
